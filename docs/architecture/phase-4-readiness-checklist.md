# Phase 4 Readiness Checklist

Phase 4 should not begin until the following decisions are complete.

## Product Decisions

- Account registration method.
- Account recovery policy.
- Multi-device policy.
- Username, phone, or email discovery policy.
- Contact request and blocking model.
- Message retention defaults.
- File retention defaults.
- Group size targets.
- Call support target.

## Security Decisions

- Audited one-to-one messaging library or implementation strategy.
- MLS library and platform support.
- Encrypted local database choice.
- OS secure storage wrapper.
- Key backup and recovery model.
- Safety number format.
- Device linking ceremony.
- Push notification privacy policy.
- Metadata retention limits.

## Backend Decisions

- API framework and hosting model.
- Database.
- Queue technology.
- Object storage provider.
- Push provider.
- Observability stack.
- Rate-limiting strategy.
- Abuse-report storage.
- Audit log retention.

## Engineering Decisions

- Monorepo or separate client/server repos.
- Environment strategy.
- CI checks.
- Release channels.
- End-to-end test strategy.
- Mobile development build strategy.
- Security test plan.
- Incident response ownership.

## Phase 4 Entry Criteria

- The UI prototype remains stable.
- Architecture docs are accepted.
- Type contracts compile.
- Backend stack is selected.
- Crypto libraries are selected.
- Threat model is scheduled before production data handling.
